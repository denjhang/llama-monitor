# 11-06 整机意外重启诊断（Strata 四卡真分片高负载下硬断电）

> 结论先行：**这是电源层面的硬断电（power loss / brownout），不是引擎 bug、不是蓝屏、不是驱动崩溃。**
> 内核没有留下任何 bugcheck 或 dump，因为断电时 CPU 连写日志的机会都没有。
> 已做软件侧唯一可做的缓解：五卡功耗上限 320W → 250W。

---

## 一、现场时间线

| 时刻 | 事件 | 来源 |
|---|---|---|
| 06:53:16 | Strata 引擎日志最后写入（三个大 prefill 正在跑：65K / 71K / 74K token） | `E:/strata-src/strata-4gpu.out.log` |
| 06:53:31 | 引擎 verbose 日志最后写入 | `E:/strata-src/strata-swift-4gpu.log` |
| 07:03:23 | **系统意外关闭** | Event 6008 |
| 07:24:43 ~ 07:26:28 | 网关仍有 4 个请求成功返回（3289 / 3076 / 7061 tok 等） | `D:/llama/tee-usage-8080.jsonl` |
| 07:28:18 | 系统重新启动 | Kernel-General 12 |
| 07:28:24 | Kernel-Power 41 记录"未正常关机" | Event 41 |

注意 07:24-07:26 那几条成功请求：机器在 07:03 前后经历了第一次掉电（日志此刻断流），
短暂恢复后继续服务，然后在 07:28 前彻底断电重启。**是两次连续掉电。**

## 二、判定依据（为什么排除软件故障）

| 检查项 | 结果 | 含义 |
|---|---|---|
| Kernel-Power 41 `BugcheckCode` | **0** | 内核没有主动触发 bugcheck → 不是蓝屏 |
| `C:\Windows\Minidump\` | **空** | 没有 minidump → 内核没走到崩溃处理流程 |
| `C:\Windows\MEMORY.DMP` | **不存在** | 同上 |
| `CrashDumpEnabled` 注册表 | **0**（已关闭） | 顺带说明：即使真蓝屏也不会留 dump，这个开关建议改成 1（小内存转储） |
| Application 日志 1000/1001 | 崩溃窗口内**无任何记录** | 没有任何进程异常退出 |
| 引擎自身 err 日志 | `strata-4gpu.err.log` **0 字节** | 引擎没有报错，是被整机拖下去的 |
| WHEA 不可纠正错误 | **0 条**（Id 1/18/20/46/47 全无） | 没有 MCE 级硬件故障记录 |

**核心判据**：`BugcheckCode=0` + 零 dump + 零应用崩溃 + 零 MCE，
唯一剩下的可能就是供电中断（市电、PSU 余量、UPS 切换）或主板 VRM 保护。

## 三、负载特征（为什么"运算稍微高一点"就炸）

崩溃前后配置刚从**假分片**切到**四卡四段真分片**：

| 项 | 假分片（10-19 ~ 11-01） | 真分片（11-02 起） |
|---|---|---|
| GPU0 负载 | 满载（跑全 48 层） | 约 1/4 |
| GPU1-3 负载 | **基本待机**（只当专家仓库，按需读） | **满载（各 12 层）** |
| 四卡同时峰值功率 | 约 320W + 3×20W | **4 × 320W ≈ 1280W** |
| PCIe 流量 | 低（专家按需拉取，命中率 98%+） | **高一个数量级**（每 token 跨 3 段传激活值） |

也就是说：假分片时代整机电源负载长期是"一张卡满血 + 三张卡打酱油"，
切到真分片后变成**四张卡同时拉满**，加上双 Xeon E5-2673v4（2×135W TDP，实际峰值更高）
和 8 条 DDR4，整机峰值功耗跨过了 PSU 的某条线。

这与用户描述"只要运算稍微高一点，整台电脑直接干到重启"完全吻合。

## 四、已做的缓解

```bash
nvidia-smi -pl 250   # 五张卡功率上限 320W -> 250W
```

从 1600W 的总上限压到 1250W。decode 速度损失可忽略（decode 是显存带宽瓶颈，
不是 SM 算力瓶颈；四段真分片实测 110.8 t/s 发生在 320W 上限下，
限到 250W 后的实测见 `Strata-四卡真分片提速定论.md` 补充节）。

**注意：`nvidia-smi -pl` 重启后失效**，需要重新执行，或者写进开机任务。
（本机当前靠手工执行，未做持久化。）

## 五、如果降功耗后仍然重启 —— 需要用户判断的硬件侧

1. **PSU 余量**：5×RTX3080(320W) + 双 Xeon + 8 DIMM 的 12V 峰值需要至少 1600W 真实输出。
   若是 1200-1500W 电源，或者电源已用 3 年以上（电容老化），高负载瞬态就会掉电。
2. **PCIe 供电线**：多卡矿架式供电若用 SATA 转 6pin/8pin，单路 12V 过载会触发保护。
   应确认每条 8pin 都是原生 PCIe 线，且不要在一条模组线串两张卡。
3. **市电 / UPS**：若是 UPS 电池老化，切换瞬间电压跌落也会造成这类"无声掉电"。

## 六、同时发现的两条独立硬件线索（与本次重启无关，但迟早要处理）

### 6.1 PCIe 链路严重降级 + 463 条 WHEA 可纠正错误

```
GPU0/1/2: pcie.link.gen.current=1  width.current=8   (理论 gen3 x16)
GPU3    : pcie.link.gen.current=1  width.current=4
GPU4    : pcie.link.gen.current=3  width.current=16  ← 唯一正常的
```

11-02 那次重启前 20 分钟内出现了 **463 条 WHEA-Logger Id=19**，
签名全部一致：`MciStat=0x8800004000310e0f / MCABank=5 / ErrorType=10 / Bus/Interconnect Error`，
跨 13 个不同的 APIC ID（0/2/6/8/16/17/20/22/24/32/34/38/40/48/53），
单分钟最高 96 条（00:58）。

bank 5 + Bus/Interconnect + 全核芯分布 = **CPU 与 PCIe 设备之间的链路训练/传输错误**，
配合 gen1 x8 的降级状态，几乎可以确定是 **PCIe 延长线或转接板质量/接触问题**，
或者插槽供电不足导致链路反复重训。

真分片的跨卡激活值传输量比假分片高一个数量级，链路降级会直接吃掉真分片的收益，
同时这些错误会持续刷 WHEA（本次 11-06 崩溃前 20 分钟是 0 条，说明那次是纯掉电、
不是链路错误引发的）。

**建议**：逐卡换线/换插槽二分定位；至少把 GPU0-3 中链路最差的 GPU3（gen1 x4）先排查。

### 6.2 磁盘 2 每天一次的 IO retry

```
10-30 11:47:41  磁盘 2  LBA 0x89a3cef0
10-30 20:35:40  磁盘 2  LBA 0x5a3640
10-31 11:47:47  磁盘 2  LBA 0x89a3cef0
11-01 10:47:18  磁盘 2  LBA 0x89a3cef0
11-02 02:04:48  磁盘 2  LBA 0x5a3640
11-03 12:24:27  磁盘 2  LBA 0x89a3cef0
11-04 23:24:31  磁盘 2  LBA 0x89a3cef0
11-06 00:12:49  磁盘 2  LBA 0x5b3a08
11-06 08:10:06  磁盘 2  LBA 0x5a3640
```

LBA 高度集中在两个地址（`0x89a3cef0` / `0x5a3640`），是**同一处坏扇区的反复重读**，
典型的盘体老化前兆。Event 153 是"重试后成功"，还没到 IO 失败，
但建议尽快把这块盘上的数据挪走并做 `chkdsk /r` 或直接更换。

## 七、复现方法（下次怀疑掉电时按这个查）

```powershell
# 1) 有没有非正常关机
Get-WinEvent -FilterHashtable @{LogName='System'; Id=41,6008} -MaxEvents 10

# 2) 关键判据：BugcheckCode 必须为 0 才是纯掉电
Get-WinEvent -FilterHashtable @{LogName='System'; Id=41} -MaxEvents 5 | ForEach-Object {
  $x = [xml]$_.ToXml()
  $d = @{}; $x.Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#' + 'text' }
  "$($_.TimeCreated)  BugcheckCode=$($d['BugcheckCode'])"
}

# 3) 有没有 MCE / 链路错误
Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-WHEA-Logger'} -MaxEvents 20 |
  Group-Object Id | ForEach-Object { "Id=$($_.Name) count=$($_.Count)" }

# 4) 有没有 minidump
Get-ChildItem C:\Windows\Minidump\ -ErrorAction SilentlyContinue
```
